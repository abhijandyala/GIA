# Functional QA Bug Log — 2026-09-08

## Test environment

- Project: `GIA.xcodeproj`
- Scheme: `GIA`
- Test target: `GIAUnitTests`
- Xcode: 26.3 (17C529)
- Simulator: iPhone 17 Pro Max, iOS 26.3, arm64
- Gateway during simulator conversation: intentionally unavailable
- Provider credential values: never printed, copied, moved, or added to the
  change set

## Resolved defects

### QA-001 — Debug build could remain on SPEAKING when the gateway was down

- Reproduction: launch the Debug app without the local gateway and begin a
  conversation.
- Observed: generated reply and system/canned fallbacks were all disabled in
  Debug, leaving the visible conversation unable to finish normally.
- Root cause: `GIAResponseCoordinator` hard-disabled both safe fallbacks for
  every Debug launch.
- Fix: safe system-voice and canned-text fallbacks are now enabled by default;
  strict provider behavior is explicitly opt-in with
  `GIA_DEBUG_STRICT_PROVIDER_FAILURES=1`.
- Safety: fallback copy contains no provider result, price, reservation, or
  confirmation claim.

### QA-002 — Existing transcript hook bypassed the real speech completion path

- Reproduction: launch with `GIA_AUTORUN_PLAN_HANDOFF_TRANSCRIPT`.
- Observed: the hook interpreted and planned directly instead of publishing the
  event used by completed live speech recognition.
- Root cause: the old helper called planning code directly.
- Fix: `VoiceSessionCoordinator.injectCompletedTranscript` now publishes the
  same `completedTranscript` and `transcriptionSequence` observed by Map. The
  launch hook and `gia://debug-transcript?text=...` route use that event.
- Scope: compiled only in Debug; production microphone capture is unchanged.

### QA-003 — Multi-part clarification answers discarded unasked-for facts

- Reproduction: after being asked for dates, answer “May 10 to May 14, 2027 for
  four travelers under $6000.”
- Observed: dates were retained, but traveler count and budget were silently
  discarded.
- Root cause: clarification parsing updated only the field currently being
  asked.
- Fix: after the required field succeeds, the normal follow-up parser merges
  every additional supported fact from the same utterance.
- Regression: dates = five days, travelers = four, budget = USD 6000, and the
  request has no remaining required-field validation issues.

### QA-004 — A Debug URL answer could be rejected between playback and listening

- Reproduction: inject a clarification while G.I.A. is speaking or immediately
  after it transitions to listening.
- Observed: the harness could attempt an invalid second `beginListening`
  transition, or the production echo guard could reject the same-run-loop
  transcript.
- Root cause: the harness did not distinguish `needsClarification`, `listening`,
  and `transcribing`, and published before stopped playback observation settled.
- Fix: state-aware transitions plus a one-turn yield before publishing the
  Debug transcript.

### QA-005 — Launch transcript could be dropped before the scene became active

- Reproduction: install a fresh Debug build and launch immediately with
  `GIA_DEBUG_INJECT_TRANSCRIPT`.
- Observed: a slower first frame could leave application activity inactive at
  the hook's single 350 ms check, permanently dropping the request.
- Root cause: startup synchronization used a one-shot delay.
- Fix: the Debug hook now waits in short bounded intervals for an active scene
  before publishing the request.

### QA-006 — Spoken questions did not visibly or reliably return to listening

- Reproduction: activate G.I.A. with the microphone and wait for “Hi there, what
  trip are you hoping to plan?” to finish.
- Observed: the disc could remain on `SPEAKING`, and the playback watchdog could
  stop audio without re-arming recognition.
- Root cause: successful playback tied the `.idle` transition to whether prompt
  text should be erased. Text-preserving conversational replies therefore kept
  the stale `.playing` state. The watchdog also attempted the handoff itself;
  its helper cancelled the watchdog task from inside that same task before the
  microphone restart could run.
- Fix: playback now always leaves `.playing` after completion while independently
  preserving prompt text. Watchdogs only unblock the owning speech task, which
  performs one cancellation-safe recognition handoff.
- Regression: a text-preserving spoken prompt must end in response state `.idle`
  with its prompt still visible before request transcription starts.

### QA-007 — A destination could lead to edit commands instead of trip details

- Reproduction: say “I want to go to Japan” while starting or revising a trip.
- Observed: the next prompt could ask what to keep, change, or remove rather than
  asking for missing dates.
- Root cause: voice-mode follow-up updates recorded validation issues but fell
  through to the update-complete path. The LLM prompt also did not explicitly
  reserve edit-command language for an existing-trip editing turn.
- Fix: incomplete updates now enter the same field-specific clarification flow
  in voice and typed modes. The LLM is explicitly constrained to the requested
  field, with a field-specific offline fallback.

### QA-008 — Listening transition flashed a gray ring

- Reproduction: watch the active disc as speech ends and recognition begins.
- Observed: the cyan speaking ring changed to a gray/white listening ring,
  making the transition resemble a second sphere flashing over the interface.
- Fix: wake, listening, processing, and speaking now share the intelligence-blue
  accent; only errors and the inactive/returning states change color family.

### QA-009 — User subtitles waited behind the previous assistant sentence

- Reproduction: begin answering immediately after G.I.A. finishes a spoken
  question.
- Observed: the previous assistant subtitle stayed visible until Apple Speech
  emitted its first partial word, making the interface look late even though
  microphone capture had already begun.
- Root cause: transcript presentation used only recognized text to decide when
  the speaker changed.
- Fix: the audio speech gate now exposes user voice activity to the UI. The old
  assistant copy clears at voice onset, the cyan disc responds immediately, and
  live partial words replace it as recognition produces them.

### QA-010 — A useful follow-up could overrun the subtitle disc

- Reproduction: complete destination, dates, and group size without optional
  details.
- Observed: the flight, hotel, and activity prompt could end in an ellipsis at
  the disc's five-line visual limit.
- Fix: both the LLM instruction and resilient fallback now keep the entire
  reply under 140 characters while retaining the key planning choices.

### QA-011 — Multi-sentence speech caused a false listening flash

- Reproduction: receive a two-sentence generated follow-up and watch the state
  label between the first and second sentence.
- Observed: the client could report `LISTENING` and then return to `SPEAKING`
  even though G.I.A. had not finished its reply.
- Root cause: the client split one response into two ElevenLabs requests. The
  first audio player's completion published a real playback-complete event
  before the second player started.
- Fix: each reply is now one uninterrupted speech request. The gateway
  prefetches that same complete normalized reply, so the client consumes one
  cached audio file without an inter-sentence state seam.

### QA-012 — Xcode Run silently used the device voice when the gateway was down

- Reproduction: press Run in Xcode while no process is listening on local port
  8787.
- Observed: OpenAI and ElevenLabs were unreachable, so the resilient system
  voice fallback spoke the response.
- Root cause: the shared Xcode scheme launched only the iOS app; the separately
  secured local gateway was not running.
- Fix: the Debug Run action now starts the gateway from the existing untracked
  `.env` when needed and waits briefly for its non-sensitive health endpoint.
  Credential values are never copied into the scheme or app.

### QA-013 — LISTENING could appear before microphone capture reopened

- Reproduction: watch the 280 ms playback-echo settling window or the interval
  while a completed transcript is being interpreted.
- Observed: domain phases such as `needsClarification` could label the UI as
  listening while the voice session was actually stopped.
- Fix: the presentation resolver now requires the live
  `requestTranscription` mode before displaying `LISTENING`; response playback
  still has priority as `SPEAKING`, and closed-microphone work is `PROCESSING`.

3. Changing several answers while preserving unchanged facts.

11. Spoken-prompt completion releases `SPEAKING` while retaining visible copy.
12. “I want to go to Japan” asks for dates, never edit commands.
13. Optional intake explicitly offers flight, hotel, and activity preferences.
14. Dynamic replies use one uninterrupted provider speech request.
15. `LISTENING` is shown only while request transcription is actually open.

Gateway tests remain fully mocked under `Gateway/test`; `npm test` does not call
billable providers. Live smoke testing is intentionally excluded.
